Complete Purchase & Reservation Flow


sequenceDiagram
    autonumber

    actor Client
    participant Gateway as API Gateway
    participant Inventory as Inventory Service
    participant Redis as Redis Cluster
    participant Lua as Lua Reservation Script
    participant DB as Inventory DB

    Client->>Gateway: POST /inventory/reserve
    Note over Client,Gateway: productId, quantity, userId

    Gateway->>Gateway: Validate JWT
    Gateway->>Gateway: Rate Limit Check

    Gateway->>Inventory: Reserve(productId, qty, userId)

    Inventory->>Redis: Execute Atomic Lua Script
    Redis->>Lua: Check stock + reservation

    Lua->>Lua: Read available stock

    alt Stock Available
        Lua->>Lua: Atomic DECR stock
        Lua->>Lua: Create reservation
        Lua->>Lua: Set TTL lease
        Lua-->>Redis: SUCCESS + reservationId
        Redis-->>Inventory: Reservation Created

        Inventory->>DB: Persist Reservation
        DB-->>Inventory: Commit

        Inventory-->>Gateway: 200 Reservation Created
        Gateway-->>Client: reservationId + expiresAt

    else Insufficient Stock
        Lua-->>Redis: FAILURE
        Redis-->>Inventory: Out of Stock
        Inventory-->>Gateway: 409 OUT_OF_STOCK
        Gateway-->>Client: Product Unavailable
    end
Payment + Transactional Outbox Flow

sequenceDiagram
    autonumber

    actor Client
    participant Gateway as API Gateway
    participant Payment as Payment Service
    participant PG as Payment Gateway
    participant DB as Order/Payment DB
    participant Outbox as Outbox Table
    participant Broker as Kafka / RabbitMQ

    Client->>Gateway: POST /checkout
    Gateway->>Payment: Process Payment

    Payment->>Payment: Validate Idempotency Key

    alt Idempotency Key Already Processed
        Payment->>DB: Fetch Existing Payment
        DB-->>Payment: Previous Result
        Payment-->>Gateway: Return Previous Result
        Gateway-->>Client: Payment Result

    else New Payment
        Payment->>PG: Charge(amount, idempotencyKey)

        alt Payment Successful
            PG-->>Payment: Payment Success

            Payment->>DB: BEGIN TRANSACTION

            Payment->>DB: Update Payment = SUCCESS
            Payment->>DB: Update Order = CONFIRMED

            Payment->>Outbox: INSERT PaymentSuccess Event

            Note over DB,Outbox: Same DB Transaction

            Payment->>DB: COMMIT

            Payment-->>Gateway: Payment Successful
            Gateway-->>Client: Order Confirmed

        else Payment Failed
            PG-->>Payment: Payment Failed

            Payment->>DB: Record Payment Failure
            Payment-->>Gateway: Payment Failed
            Gateway-->>Client: Payment Failed
        end
    end

    Note over Outbox,Broker: Asynchronous Publishing

    loop Outbox Polling
        Outbox->>Outbox: Find unpublished events
        Outbox->>Broker: Publish PaymentSuccess
        Broker-->>Outbox: ACK
        Outbox->>Outbox: Mark event Published
    end
Payment Success + Order Service Crash + Recovery

sequenceDiagram
    autonumber

    participant Payment as Payment Service
    participant Order as Order Service
    participant DB as Order DB
    participant Outbox as Outbox Table
    participant Dispatcher as Outbox Dispatcher
    participant Broker as Message Broker

    Payment->>Order: PaymentSuccess Event

    Note over Order: Order Service receives event

    Order->>DB: BEGIN TRANSACTION
    Order->>DB: Update Order = CONFIRMED
    Order->>Outbox: Insert OrderConfirmed Event

    Note over Order: SERVICE CRASHES

    Order--xDB: Connection Lost
    Note over DB,Outbox: Transaction rolled back or committed atomically

    rect rgb(255,235,235)
        Note over Dispatcher,Outbox: Recovery Worker Starts
    end

    loop Periodic Recovery Poll
        Dispatcher->>Outbox: SELECT unpublished events
        Outbox-->>Dispatcher: OrderConfirmed Event

        Dispatcher->>Broker: Publish OrderConfirmed
        Broker-->>Dispatcher: ACK

        Dispatcher->>Outbox: Mark Event Published
    end

    Broker->>Order: OrderConfirmed Event

    Order->>Order: Idempotency Check

    alt Event Already Applied
        Order-->>Broker: ACK
    else Event Not Applied
        Order->>DB: Apply Event
        Order->>DB: Commit
        Order-->>Broker: ACK
    end
